# Java 25 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run noir on JDK 25 and accept repositories whose `maven.compiler.release` is 17–25.

**Architecture:** One builder and one grader image on JDK 25; Maven compiles with each repository's own release. The seal check's release assumption becomes a range.

**Tech Stack:** Docker (Temurin 25), Maven 3.10.0, PIT 1.30.2, JaCoCo 0.8.16, JUnit console launcher 6.1.3.

**Spec:** `docs/superpowers/specs/2026-11-06-noir-java-25-design.md`

## Global Constraints

- Builder base `maven:3.10.0-eclipse-temurin-25-noble`; grader base `eclipse-temurin:25-jdk-noble`.
- `pitest-command-line` 1.30.2; JaCoCo 0.8.16, `pitest-junit5-plugin` 1.2.3, JUnit console 6.1.3 unchanged.
- Accepted releases: integers 17–25 inclusive. Rejection text exactly `maven.compiler.release must be from 17 to 25 (found <value>|unset)`.
- No change to the analyzer, Examiner, grader script, commitment, `spec.json` or issue format.

## Review Focus

1. A release given as a property expression that Maven resolves (e.g. `${java.version}` = 25) is judged by its resolved value — `SealJudgeTest.resolvedReleaseIsJudged` (the seal already reads Maven's evaluated value; the test pins it).
2. Release `21` repositories still build, measure and grade on the JDK 25 images — the existing Docker ITs.
3. Java 25 bytecode works with JaCoCo and PIT — `ContainerMeasureRunnerIT.java25RepositoryIsMeasured`.
